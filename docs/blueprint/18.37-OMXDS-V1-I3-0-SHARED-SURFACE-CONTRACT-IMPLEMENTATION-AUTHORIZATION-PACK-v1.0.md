## 1. Decisión

Founder autoriza exclusivamente I3-0: un contrato interno compartido para familias, estados, procedencia, omisiones y una CTA dominante, más su harness. La implementación no conecta consumidores públicos ni cambia renderers, rutas o SEO.

## 3. Contrato implementado

- vocabulario de estados compartido con I2: `ready`, `loading`, `empty`, `partial_error`, `total_error`, `offline` y `no_media`;
- procedencia obligatoria, explícita como fixture o fuente gobernada;
- omisiones cerradas para no inventar información ausente;
- máximo una acción dominante y exactamente una cuando el estado es `ready`;
- `href` interno seguro y lista cerrada de acciones no comerciales;
- compra, checkout y reserva no forman parte del vocabulario;
- fixtures de prueba inequívocamente ficticios.

## 4. Frontera del flag y fallback

`surface-contracts-flag.server.ts` sólo reexporta la constante y el lector server existentes. No crea setting, migración, endpoint ni flag. La fila existente permanece en `false`; cualquier ausencia, error o excepción conserva el retorno fail-closed del lector original.

I3-0 no invoca el lector desde rutas o componentes. Por ello OFF conserva exactamente el renderer, HTML, SEO y comportamiento público vigentes.
