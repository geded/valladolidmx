# 19.29 · G4-SYSTEM-02 · Adopción del runtime visual premium en los previews G4 (v1.0)

- **Estado:** `Approved`
- **Dominio:** `D01 · product-governance`
- **Depende de:** `docs/blueprint/19.28-G4-SYSTEM-01-PREMIUM-VISUAL-RUNTIME-v1.0.md`
- **Autorización de producto:** `docs/governance/product-authorizations/PCA-2026-032.json`
- **Flag:** `omxds_visual_v1_contracts_enabled = false` (sin cambios)

## 1. Objetivo

Eliminar las implementaciones locales de Hero, Galería y Breadcrumb de las seis
vistas previas internas G4 (Home, Destino, Hotel, Restaurante, Experiencia y
Evento) y hacer que todas consuman el runtime visual premium compartido
introducido por `19.28`, a través de una capa única de mappers ViewModel.

No se tocan rutas públicas, datos, migraciones, `status`, `is_demo_seed`,
producción, merge ni despliegue. El flag global permanece `false`.

## 2. Alcance implementado

### 2.1 Capa de mappers ViewModel (P1)

- `src/lib/omxds/presentation/vm/common.ts` — primitivas de normalización:
  `toPremiumMediaVM`, `toPremiumFactsVM`, `toPremiumBadgesVM`,
  `toPremiumGalleryVM`, `toPremiumHeroVM`, `toPremiumCrumbs`.
  Reglas fail-closed: un medio sólo se emite si tiene URL pública estable y
  ALT humano; el distintivo Pueblo Mágico se emite en texto salvo que exista
  asset institucional acreditado; el breadcrumb territorial es canónico
  (`Inicio → Oriente Maya de Yucatán → Destino → …`).
- `src/lib/omxds/presentation/vm/families.ts` — un único constructor
  `toPremiumSurfaceVM` y los mappers por familia (`toHomePremiumVM`,
  `toDestinationPremiumVM`, `toHotelPremiumVM`, `toRestaurantPremiumVM`,
  `toExperiencePremiumVM`, `toEventPremiumVM`) más `toPremiumSectionVM`.
- `src/lib/omxds/presentation/vm/index.ts` — punto único de exportación.

### 2.2 Adopción en los previews G4 (P2)

Los seis previews internos dejan de declarar Hero/Galería/Breadcrumb propios y
pasan a declarar únicamente una **fuente plana** (`*_SOURCE` / `build*Source`)
que alimenta el mapper de su familia:

| Vista previa interna | Fuente | Mapper |
| --- | --- | --- |
| `/lovable/g4-home-premium-preview` | `buildHomeSource` | `toHomePremiumVM` |
| `/lovable/g4-destination-microsite-preview` | `DESTINATION_SOURCE` | `toDestinationPremiumVM` |
| `/lovable/g4-hotel-premium-preview` | `HOTEL_SOURCE` | `toHotelPremiumVM` |
| `/lovable/g4-restaurant-premium-preview` | `RESTAURANT_SOURCE` | `toRestaurantPremiumVM` |
| `/lovable/g4-experience-premium-preview` | `EXPERIENCE_SOURCE` | `toExperiencePremiumVM` |
| `/lovable/g4-event-premium-preview` | `buildEventSource(status)` | `toEventPremiumVM` |

`src/components/premium/PremiumHero.tsx` recibe una única extensión
compatible hacia atrás: la ranura opcional `extras`, usada por la portada para
alojar el control de slides sin duplicar el Hero.

Los paneles locales de afinación (dirección visual, galería, rol, estado del
evento, secciones) se conservan intactos y sin persistencia.

### 2.3 Gate contractual (G5)

`scripts/omxds/g5/premium-presentation.contract.test.ts` verifica:

1. resolución fail-closed de presentación y actor;
2. saneamiento de medios (URL estable + ALT obligatorio);
3. breadcrumb territorial con la etiqueta canónica “Oriente Maya de Yucatán”;
4. que los mappers sean puramente de presentación (sin Supabase ni acceso a
   datos);
5. que los previews G4 no reintroduzcan primitivas Hero/Galería propias.
