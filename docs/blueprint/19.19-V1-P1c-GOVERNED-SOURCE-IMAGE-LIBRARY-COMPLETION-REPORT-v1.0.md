## 6. Compatibilidad evolutiva

- **Sustitución por fotos reales:** Cada foto real futura se ingiere como un nuevo
  `media_asset` (nuevo id) y se reasigna la portada/galería de la ficha. El original
  generado queda archivado en el bucket de originales (sin borrar, por trazabilidad).
  Cero URLs rotas, cero pérdida de datos. (Founder Immutable Original Principle.)
- **Derivación:** Los consumidores nunca construyen URLs/paths — sólo `resolveMediaSource()`.
  Las URLs de `media-derived` no son canónicas (Founder Stable Public Asset Contract).
- **Elegibilidad premium por ficha:** Queda desbloqueada en términos de disponibilidad de
  assets gobernados, pero el cierre del flujo (portal provenance + plan grant + audit log)
  corresponde a V1-P1.d (Demo Pack), no a esta ola.

## 10. Hardening Carril-B · Exclusión de auto-gen del lint gate

Durante la ejecución de V1-P1.c el gate `lint` falló por drift de formato en
`src/integrations/supabase/previewAuthStorage.ts` — un archivo auto-generado
(encabezado "This file is automatically generated. Do not edit it directly.")
regenerado por la plataforma el 2026-08-25 06:11, fuera del control del
desarrollador y prohibido de editar manualmente. El mismo caso que
`src/integrations/supabase/types.ts`, que ya estaba excluido del lint.

Corrección durable (Carril-B, no product code, no auto-gen):
- `scripts/lint/lint-baseline.mjs`: `previewAuthStorage.ts` añadido a `excludedPaths`
  y `aggregate()` ahora filtra los paths excluidos (antes la exclusión era sólo
  metadatos y no evitaba el conteo de NEW_DEBT).
- `scripts/lint/lint-baseline.json`: `excluded_paths` sincronizado con el nuevo array.

Resultado: lint PASS (7977 errores históricos, 0 NEW_DEBT). No afecta lógica de
producto, no modifica archivos auto-gen, no activa flags ni producción.
