# Alux rules

- Browser sessions are server-issued with an HttpOnly device proof hashed on the existing session row; chat, memory, contact capture and account binding verify ownership through `session-ownership.server.ts`. Legacy unproved anonymous rows remain stored but cannot be claimed by identifier. Why: identifiers alone cannot authorize private memory or cross-account linkage.
- Both web conversation entries share the atomic `alux.public_message` quota before any AI call; speech-to-text, text-to-speech and uncached UI translation use separate tools in the same public quota helper. Why: simultaneous requests and auxiliary intent AI cannot bypass a read-only message count or create unbounded provider spend.

- Channel switches: web, WhatsApp and embed on/off live as `channel_*` keys inside `alux_settings.flags` (`channels.ts`); a missing key means on, every writer merges flags instead of replacing them, and servers enforce them (`aluxConverse`, `/api/public/alux/chat`, WhatsApp reply and outbox), never only the UI. Why: one settings row, instant kill switch, older console saves cannot reset channels.
- Training: a destination brief is the Knowledge Base entry `destino-<slug>` (category `destinos`) injected into web and WhatsApp prompts; unanswered questions go only through `recordKnowledgeGapServer` (PII-scrubbed, best-effort, service-role RPC) into `alux_knowledge_gaps`. Why: reuse the existing KB authority and never let training break or leak a reply.
- Embed: partner sites load `public/alux-embed.js`; `/api/public/alux/embed-status` issues a 15-minute HMAC grant only for `flags.embed_hosts`, and `/insertar/alux` accepts host/destination/business exclusively from that grant (never raw URL claims). `flags.embed_sites` still wins over snippet blanks and `embed-context.server.ts` validates published content; the frame gets no microphone/geolocation/clipboard permission. Why: one chat authority, controlled AI cost, and no forged partner attribution.
- CMS reading: every Alux channel (dock, public/embed chat, WhatsApp) reads published content through `retrieveConverseCandidates`, choosing rows by `converse-priority.ts` (question words, paid `alux_weight` from `business_effective_visibility`, online-sale bonus, profile quality from `business_profile_signals` via `aluxQualityScore`, daily fair-turn tie-break) instead of alphabetical caps; online-sale prices only via `productOfferFacts`, everything else as reference price. Why: alphabetical caps hid whole businesses, and one price rule keeps every channel consistent.
- Paid visibility in recommendations: `rankConverseCandidates` lifts at most one paid candidate per family to the top only when it matches the request, and the card discloses it as «Recomendado»; a candidate carries `aluxWeight` only when `aluxCanPromote` allows it (plan with proactive mentions, under its `alux_daily_cap` counted from `business_view_events` `alux_mention` rows written by `paid-mentions.server.ts`), otherwise the weight only orders reading. Why: Founder chose Google-style sponsored placement with disclosure, bounded by each package's daily allowance.
- Table booking in Alux: business candidates with the `mesas` online-sales mode carry a «reservar mesa» fact and, when the question asks for a table, link to the page's `#reservar-mesa` block; Alux never books itself or sees guest contact data. Why: one booking authority (`TableBookingWidget`/`restaurant_book`) that survives syncing Alux's conversational rules from Zazil.
